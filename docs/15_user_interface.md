# Пользовательский интерфейс SMS Guard

## Цель задания

Задание №15 добавляет HTML-интерфейс к REST API задания №14. Страницы используют Django Templates, существующий Bootstrap 5.3.3, обычный CSS и JavaScript. Анализ выполняется существующими сервисами backend.

## Страницы

| Путь | Содержимое | Доступ |
|---|---|---|
| / | Стартовая страница с переходами к проверкам | Публичный |
| /login/ | Логин, пароль, ссылка на регистрацию | Публичный |
| /register/ | Логин, email, пароль и его подтверждение | Публичный |
| /check/sms/ | Поле SMS, счётчик, три примера, результат | После входа |
| /check/url/ | Поле адреса, результат отдельной ссылки | После входа |
| /checks/<id>/ | Загрузка сохранённого результата | Только владелец |

После успешного входа выполняется переход на /check/sms/. Регистрация использует прежний API и предлагает затем войти. Вошедшего пользователя страницы входа и регистрации направляют к проверке SMS. Выход использует POST auth/logout/ с CSRF.

Стартовая страница заменяет устаревшее описание каркаса рабочими переходами. Полноценная история, профиль и Dashboard остаются отдельными заданиями.

## Подключение к API

Транспорт использует fetch с credentials: "same-origin", JSON и заголовком X-CSRFToken. SMS отправляется в POST /api/v1/check/sms/ в виде {"text": "..."}, URL в POST /api/v1/check/url/ в виде {"url": "..."}. Успешный контракт backend возвращает HTTP 201. Анализ и формула риска выполняются на сервере.

Submit обрабатывается через preventDefault. На время запроса показывается spinner и блокируется кнопка. aria-busy предотвращает повторную отправку. Обработчики try/catch/finally возвращают кнопку в рабочее состояние при успешном ответе, ошибке HTTP, сетевом сбое или отмене по таймауту 30 секунд.

Проверяется непустой ввод и длина в 1000/2048 символов. SMS-счётчик обновляется при вводе, выборе примера и очистке. Три искусственных примера заполняют только поле. Их названия обозначают сценарий, фактический результат определяет модель. Домен в примерах относится к зоне .example. URL без схемы разрешён.

Страница /checks/<id>/ выполняет только GET /api/v1/checks/{id}/. Дополнительный анализ при открытии записи отсутствует. Перед показом HTML проверяется владелец Check. Для чужого или отсутствующего id возвращается 404. Маскированный ввод берётся из masked_input.

## Результат анализа

SMS-карточка показывает категорию с русской подписью и символом, название уровня риска, число Risk Score, шкалу 0–100, P_sms, P_url_max, язык, группы социальной инженерии, объяснение, рекомендацию, предупреждение и время проверки. Вложенные URL показываются с собственными P_url, категориями, признаками и объяснениями.

Вероятности форматируются для русского языка с точностью до двух десятичных знаков в процентах. Исходные числовые значения JSON при выводе не изменяются. Для p_url_max = null выводится «Ссылки не обнаружены».

Для отдельного URL показываются адрес, домен, P_url, категория, признаки, объяснения и предупреждение. При risk_score = null шкала и нулевой балл не подставляются.

SAFE имеет зелёную подпись, SUSPICIOUS жёлтую, FRAUDULENT и DANGEROUS красную. Категории различаются также текстом и символом. Цвета интерфейсных действий синие, остальные поверхности нейтральные.

## Сессии и CSRF

HTML-представления используют существующую Django-сессию. Защищённые страницы перенаправляют анонимного пользователя на /login/. Формы не создают отдельную систему хранения пользователей.

Django генерирует маскированный CSRF-токен через csrf_token в шаблоне. JavaScript берёт его из DOM, поскольку csrftoken-cookie имеет HttpOnly. Cookie отправляются браузером автоматически. После входа загружается новая защищённая страница с актуальным токеном. Значения токенов, паролей и сессий в localStorage/sessionStorage не записываются.

## Безопасность вывода

Пользовательский ввод, URL, объяснения, рекомендации и ошибки выводятся через textContent и createElement. Динамический HTML не используется. URL анализируется локальным браузерным парсером только для выделения имени хоста, без сетевого запроса.

Найденные адреса выводятся элементами code и strong. Они не получают href/src. Единственная создаваемая JS-ссылка ведёт на внутренний /checks/<id>/ и строится из проверенного положительного целого ID. Записи с маскированными адресами остаются маскированными.

Шаблоны используют стандартное Django-экранирование. Технические 5xx и неожиданные ответы заменяются понятным сообщением, traceback и пути не выводятся. Для 400 используется безопасное сообщение валидации из установленного контракта API. Обработаны 401, 403, 404, 429, 503, сеть, таймаут и невалидный JSON.

## Адаптивность и доступность

Bootstrap Grid переключает двухколоночную форму на одну колонку. Навигация переносится, кнопки на узком экране занимают доступную ширину. Для длинных URL и маскированного текста применяется overflow-wrap: anywhere. Поля имеют связанные label, ошибки используют aria-live и role=alert, результат может получить клавиатурный фокус.

Расчёт контраста основных заданных пар цветов дал значения от 5,70 до 13,20 к 1. Категории имеют контраст 6,49–7,28 к 1, основная кнопка 6,70 к 1. Полный визуальный и клавиатурный аудит требует браузера.

## Ограничения моделей

Модель текста обучена на английском spam-корпусе. Оценка русских и казахских SMS менее надёжна, соответствующие предупреждения API сохраняются в карточке. Spam не всегда означает мошенничество.

URL-модель зависит от артефактов исходного датасета. Фактическая проверка example.com в этом прогоне дала DANGEROUS с P_url 1. Предупреждение о возможной ошибочной оценке известных безопасных сайтов сохраняется и в форме, и в объяснениях результата. При демонстрации важно читать причины и предупреждения вместе с категорией.
