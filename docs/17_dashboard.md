# Задание №17. Панель мониторинга и визуализация

## Цель и структура

Dashboard заменяет прежнюю главную страницу по `/` и доступен после входа. Анонимный запрос перенаправляется на `/login/?next=/`. Используются существующие Django Templates, Bootstrap 5.3.3, стили SMS Guard и Chart.js 4.4.8 через CDN. Отдельной сборки frontend и новых Python-зависимостей нет.

Страница загружает данные из прежнего `/api/v1/stats/summary/` при каждом открытии. Переключение периода повторяет запрос и обновляет URL страницы. Навигация содержит Dashboard, проверки SMS/URL, историю, профиль и существующий выход.

Новые файлы

- `apps/dashboard/statistics.py` — период, ORM-агрегаты и безопасный ответ статистики.
- `static/js/dashboard.js` — запрос через GuardUI, карточки, три графика, таблицы и состояния загрузки/ошибок.
- `tests/test_dashboard.py` — проверки Dashboard и производительности.
- `docs/17_dashboard.md` — этот отчёт.

Изменённые файлы

- `apps/dashboard/views.py` — защита главной страницы и валидация периода.
- `apps/analysis/views.py` — расширение существующего SummaryView.
- `templates/dashboard/index.html`, `templates/base.html`, `static/css/style.css` — панель, навигация и адаптивные карточки.
- `tests/test_api.py` — два прежних сравнения полного JSON адаптированы к добавочным полям, все ожидания прежних четырёх полей сохранены.
- `tests/test_task02.py` — два теста главной страницы выполняются после входа согласно новому требованию №17.

Модели, миграции, API авторизации и маршруты заданий №14–16 сохранены. Рабочая база перед проверками скопирована в отдельную резервную SQLite в рабочей папке Codex `work/task17`. Демонстрационные проверки создавались в отдельной базе.

## Карточки и графики

| Карточка | Расчёт |
| --- | --- |
| Всего проверено SMS | Count по type=sms |
| Всего проверено URL | Count по type=url |
| Безопасных проверок | Категория SAFE |
| Подозрительных проверок | Категория SUSPICIOUS |
| Опасных проверок | Сумма FRAUDULENT и DANGEROUS |
| Средний Risk Score | Avg(risk_score), SQL автоматически исключает NULL |

При отсутствии числовых оценок среднее равно JSON null и отображается знаком «—». Оценка 0 входит в среднее.

FRAUDULENT относится к категории мошеннических SMS, DANGEROUS — к опасным URL. Для сводки они объединены в «Опасные». В исходных записях, `categories` API и подробных результатах сохраняются первоначальные категории. Сводная метка не является новой категорией модели и не изменяет алгоритм анализа. Искусственные записи существующей seed_demo учитываются как сохранённые проверки, их исходные категории сохраняются.

Три графика

1. Кольцевая диаграмма категорий. SAFE обозначен зелёным, SUSPICIOUS жёлтым, FRAUDULENT/DANGEROUS красным. Есть заголовок, легенда и таблица фактических чисел.
2. Линейный график проверок по дням с тремя рядами. Ось X — дата, Y — количество проверок. Пропуски календарных дней заполнены нулями. Числа доступны в раскрываемой таблице.
3. Столбчатая диаграмма пяти самых частых групп социальной инженерии. Рейтинг рассчитан из DetectedFeature, названия берутся из существующего GROUP_NAMES. Оси подписаны, числовая таблица находится под графиком.

Chart.js подключён по закреплённому адресу версии 4.4.8. Для canvas заданы доступные названия, числовые таблицы доступны независимо от графиков. Использованы подходы из официальных руководств. [Подключение Chart.js](https://www.chartjs.org/docs/latest/getting-started/), [доступность canvas](https://www.chartjs.org/docs/latest/general/accessibility.html).

При недоступности CDN выводится сообщение, карточки и таблицы продолжают работать. При отсутствии проверок числовые карточки равны нулю, среднее отсутствует, графики скрыты с пояснениями «Нет данных», доступна ссылка «Проверить SMS». Нулевые значения по календарным дням остаются в таблице. Ошибка API отображается отдельно с кнопкой повторной загрузки. При отключённом JavaScript показана ссылка на историю.

## Период и агрегации

Поддерживаются ровно строки `7`, `30`, `90`, по умолчанию `30`. Некорректное значение даёт HTTP 400 и в API, и на странице. Параметр страницы и API называется period.

Период содержит текущий календарный день и предшествующие N−1 дней в текущем часовом поясе Django. Начальная полночь включена, полночь следующего дня исключена. Границы построены как aware datetime, фильтрация выполняется по created_at. TruncDate использует тот же часовой пояс. Будущие календарные дни исключены. Все карточки, графики и последние записи используют одну и ту же выборку периода. Справочник активных версий моделей относится к текущему состоянию приложения и от периода проверок не зависит.

SQL выполняет aggregate/Avg/Count для карточек, GROUP BY category для категорий, TruncDate и GROUP BY для дней. DetectedFeature группируется по code с Count DISTINCT check_record_id. Повтор одного кода в одной проверке учитывается один раз. При равных количествах порядок определяется по code. На уровне SQL рейтинг ограничен пятью строками, последние проверки десятью строками. Используются существующие индексы Check(user, created_at) и category, дополнительных миграций нет.

В Python заполняются только ограниченный календарь до 90 дней и объединённые категории уже посчитанных SQL-агрегатов. Все проверки для группировки не извлекаются. Последние записи читаются через values только с необходимыми полями, поэтому N+1 для пользователей отсутствует.

## API статистики

`GET /api/v1/stats/summary/?period=30`, требуется существующая Django-сессия. Прежние поля sms_count, url_count, average_risk_score и categories сохранены. Их значения теперь относятся к выбранному периоду. Клиентам, которые ожидали показатели за всё время, необходимо учитывать это изменение семантики.

| Поле | Значение |
| --- | --- |
| sms_count, url_count | Количество SMS и URL |
| average_risk_score | Среднее или null |
| categories | Счётчики первоначальных категорий |
| safe_count, suspicious_count, dangerous_count | Счётчики сводных групп |
| period, date_from, date_to, timezone | Выбранные дни и часовой пояс |
| scope | current_user либо all_users |
| category_distribution | Три элемента category/label/count |
| daily | N элементов date/SAFE/SUSPICIOUS/DANGEROUS |
| top_features | До пяти элементов code/title/count |
| recent_checks | До десяти элементов id/created_at/type/category/risk_level/risk_score/detail_url |
| active_models | У администратора сведения об активных моделях, у пользователя пустой список |

## Пользователь, администратор и приватность

Обычный пользователь получает только свои проверки, агрегаты и признаки. Query-параметры user, scope или is_staff не влияют на права. Администратор определяется только серверным request.user.is_staff и получает агрегаты и последние записи всех пользователей.

Таблица последних проверок содержит дату, тип, исходную категорию, уровень риска, Risk Score и действие. Сортировка created_at/id по убыванию. В административной сводке для чужой записи detail_url=null и отображается «Доступно владельцу». Для собственной записи показана существующая ссылка `/checks/<id>/`. Это сохраняет требование №16 о 404 для чужих подробных результатов, включая доступ сотрудника. Тексты и маскированные фрагменты в Dashboard не выводятся.

В active_models возвращаются тип, версия, алгоритм, дата обучения и выбранные конечные числовые метрики из сохранённого metrics_json. Неактивные версии скрыты. Если активных SMS/URL нет в таблице, вызывается уже существующий sync_model_versions, который читает метаданные и обновляет справочник без обучения. Если файлов метаданных нет, отсутствующие значения не выдумываются. Блок не зависит от периода проверок.

Check.input_text, masked_input, result_json, URL, email, пароли и прочие исходные поля в статистический ответ не включаются. Не выполняется вызов ML или повторная оценка Test. Пользовательские строки выводятся через textContent. Внутренние ссылки строятся локально из числового ID, строковый URL API не присваивается напрямую href. Существующая CSRF-защита и лимит анализа не меняются.

## Производительность и тестирование

В tests/test_dashboard.py создаются отдельные 1000 искусственных Check и 1000 связанных DetectedFeature в тестовой базе Django. bulk_create выполняется до начала измерения. API измеряется через Django test Client, включая аутентификацию, ORM, сериализацию и middleware. HTML измеряется отдельно. Число SQL-запросов фиксируется до следующего HTTP-запроса, чтобы сброс диагностического журнала Django не исказил результат.

| Измерение | API | HTML | SQL API |
| --- | --- | --- | --- |
| Отдельный запуск теста производительности | 0,136523 с | 0,030494 с | 7 |
| В составе полного прогона | 0,019511 с | 0,003125 с | 7 |

В обоих измерениях серверные запросы укладываются в 2 секунды на текущем компьютере. Это измерение обычного пользователя на SQLite. HTML-ответ содержит каркас, затем браузер отдельно загружает API и Chart.js. Полная загрузка в браузере, сеть, отрисовка canvas и другие компьютеры по этим измерениям не оценивались.

Новые тесты покрывают вход, шесть карточек, NULL и нулевые оценки, объединение категорий, реальные даты, нулевые дни, календарные границы часового пояса, фактический топ-5, лимит последних десяти, три периода и неверные значения, изоляцию пользователей, администратора, метаданные, отсутствие исходных текстов, пустую базу, обновление после API-проверки и производительность.

Дополнительно выполнены node --check и проверка JavaScript в имитированном DOM для нормальной загрузки, смены периода с уничтожением старых Chart, пустого ответа, отсутствия библиотеки графиков и ошибки API. Это проверка логики с заменой Chart тестовым объектом. Настоящий браузер и визуальная отрисовка Chart.js отдельно не проверялись.

Итог 14.11.2026 — `401 passed in 192.63s`, включая 27 новых тестов Dashboard и 374 прежних с описанной адаптацией четырёх проверок. Новый уникальный каталог полного прогона находился в системном TEMP, ошибок WinError 5 не возникло. Отдельный начальный прогон Dashboard и проверок задания №2 дал 31 passed.

## Запуск на Windows

Из корня существующего проекта выполнить команды PowerShell.

```powershell
.\.venv\Scripts\Activate.ps1
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py runserver
```

Откройте `/login/`, войдите и перейдите на `/`. Для демоданных используйте существующую seed_demo с собственным паролем по инструкции задания №16. Для справочника моделей предусмотрена команда `python manage.py sync_model_versions`, также Dashboard синхронизирует отсутствующие активные версии при административном запросе.

Полный тестовый запуск с новым каталогом в системном TEMP при каждом выполнении

```powershell
$dashboardTestTemp = Join-Path $env:TEMP ('sms_guard_task17_' + [guid]::NewGuid().ToString('N'))
python -m pytest -q -p no:cacheprovider --basetemp=$dashboardTestTemp
```

Прежние временные папки задания №16 не используются и не удаляются. Без подключения Chart.js к CDN доступны числовые таблицы, но сами графики не отображаются. Без JavaScript доступна серверная история. Локальные модели, метаданные, датасеты, разбиения, Risk Score и словарь социальной инженерии этим заданием не изменяются.
