# Задание №9 — извлечение признаков URL

## Цель и границы

Модуль `ml/url_features.py` анализирует URL исключительно как строку и возвращает 22 числовых признака. HTTP-запросов, DNS-разрешения, открытия страниц и переходов по редиректам нет. URL-модель, датасеты, интерфейс Django и задания №10–11 не реализуются. Зависимости и SMS-модели не изменены.

## Три основные функции

- `validate_url(url) -> urllib.parse.SplitResult`: проверяет ввод и возвращает разобранный URL. Разрешены HTTP/HTTPS, включая регистр `HTTPS`. Если схемы нет, `http://` добавляется только для разбора. Также допускается запись `//example.com/path`. Исходная строка не изменяется. Поддерживаются домены, Unicode/IDNA, IPv4 и IPv6 в квадратных скобках. Максимум — 2048 символов исходного ввода. Проверяются hostname, IDNA-метки (до 63 ASCII-символов каждая), длина ASCII-host до 253 символов и порт 0–65535. Пробелы, управляющие символы и обратный слеш отклоняются. Пустые порты и некорректные IP отклоняются. При ошибке функция выдаёт собственный `ValueError` с русским сообщением; ошибки `urllib.parse` и IDNA перехватываются. Ошибку следует обработать вызывающему коду.
- `extract_url_features(url) -> dict`: вызывает валидацию, извлекает признаки в порядке таблицы ниже. Тип каждого значения — именно `int` или `float`; флаги — целые 0/1. При неверном URL не возвращает фиктивный набор нулей, а сообщает ту же ошибку валидации.
- `explain_url(features) -> list[str]`: возвращает русские объяснения активных признаков IP, порта, `@`, двойного слеша, сокращателя, ключевых слов, Punycode, смешения алфавитов, сходства с брендом, потенциальной зоны риска и отсутствия HTTPS. Для числовых счётчиков не вводятся произвольные пороги опасности. Функция не присваивает ссылке класс, вероятность или итоговый вердикт.

`host` в таблице — `hostname` без userinfo, порта, скобок IPv6 и одной завершающей точки, в нижнем регистре. Его длина, цифры, дефисы и энтропия вычисляются по этой форме исходного представления. Поэтому Unicode и Punycode одного домена могут иметь разные длины и энтропию. Для определения доменных частей и сокращателей используется каноническая IDNA ASCII-форма, для смешения алфавитов и расстояния до брендов — декодированная Unicode-форма.

## Все 22 признака

| № | Ключ | Тип | Расчёт |
|---:|---|---|---|
| 1 | `url_length` | int | Длина исходной строки, без искусственно добавленной схемы |
| 2 | `host_length` | int | Длина host |
| 3 | `path_length` | int | Длина пути из `urlsplit`, без query и fragment |
| 4 | `dot_count` | int | Количество `.` во всём исходном URL |
| 5 | `subdomain_count` | int | Количество меток `subdomain`, выделенного `tldextract`; для IP — 0 |
| 6 | `host_hyphen_count` | int | Количество `-` в host |
| 7 | `digit_count` | int | Количество ASCII-цифр 0–9 в исходном URL |
| 8 | `host_digit_ratio` | float | Число ASCII-цифр в host / длина host |
| 9 | `special_char_count` | int | Суммарное число символов из `@ ~ % = & _ ?` во всём URL; пробел не входит в набор |
| 10 | `is_ip` | int | Host является корректным IPv4 или IPv6 по `ipaddress` |
| 11 | `is_https` | int | Схема HTTPS; без схемы — 0 |
| 12 | `has_nonstandard_port` | int | Явный порт отличается от 80 и 443; без порта — 0 |
| 13 | `has_at` | int | Символ `@` присутствует где-либо в URL |
| 14 | `has_double_slash_path` | int | `//` присутствует именно в path, не в схеме или query |
| 15 | `is_shortener` | int | Host совпадает с одним из 20 сокращателей либо является его поддоменом |
| 16 | `suspicious_keyword_count` | int | Сумма вхождений 17 ключевых слов в URL без учёта регистра, включая повторные вхождения |
| 17 | `has_punycode` | int | Каноническая IDNA-форма содержит метку `xn--`; работает и для Unicode-ввода |
| 18 | `has_mixed_scripts` | int | В декодированном host одновременно есть латинские и кириллические буквы, включая зону |
| 19 | `is_brand_similar` | int | Зарегистрированный домен не совпадает с известным и имеет расстояние Левенштейна 1–2 до одного из 24 брендовых доменов |
| 20 | `host_entropy` | float | Энтропия Шеннона `−Σ p(c) log₂ p(c)` всех символов host, включая точки |
| 21 | `has_suspicious_tld` | int | Последняя метка публичного суффикса входит в фиксированный список потенциальных зон риска |
| 22 | `query_param_count` | int | Число пар `parse_qsl(..., keep_blank_values=True)`; повторные имена, пустые значения и параметры без `=` учитываются отдельно |

Отсутствующие query, path, порт и поддомены дают соответствующие нули. Host обязателен, поэтому деления на ноль нет. Счётчики исходной строки и ключевые слова не декодируют `%xx`: это зафиксированное ограничение лексического анализа.

## Домены, списки и маскировка

`tldextract.TLDExtract(suffix_list_urls=(), cache_dir=None, fallback_to_snapshot=True, extra_suffixes=('test',))` использует встроенный снимок Public Suffix List. Сетевое обновление и дисковый кеш отключены. Для зарезервированной зоны `.test` явно добавлен локальный суффикс. Частные суффиксы PSL не включаются. При неизвестном публичном суффиксе используются результаты библиотеки: зарегистрированный домен может отсутствовать, тогда сходство с брендом не проверяется. Наличие и актуальность домена в DNS не проверяются.

Список сокращателей: `bit.ly`, `tinyurl.com`, `t.co`, `goo.gl`, `ow.ly`, `is.gd`, `buff.ly`, `rebrand.ly`, `cutt.ly`, `shorturl.at`, `tiny.cc`, `rb.gy`, `lnkd.in`, `youtu.be`, `v.gd`, `clck.ru`, `s.id`, `bl.ink`, `short.io`, `trib.al`. Это фиксированный учебный список, а не проверка текущей доступности сервисов. Например, `bit.ly.example.com` сокращателем не считается.

Бренды: `kaspi.kz`, `halykbank.kz`, `homebank.kz`, `forte.kz`, `bcc.kz`, `sberbank.ru`, `tinkoff.ru`, `paypal.com`, `google.com`, `microsoft.com`, `apple.com`, `amazon.com`, `facebook.com`, `instagram.com`, `whatsapp.com`, `telegram.org`, `netflix.com`, `ebay.com`, `yahoo.com`, `yandex.ru`, `mail.ru`, `github.com`, `dropbox.com`, `booking.com`. Список используется только для строкового сравнения. Расстояние Левенштейна реализовано самостоятельно методом динамического программирования: вставка, удаление и замена стоят по единице. `login.google.com` не вызывает признак сходства: его зарегистрированный домен точно совпадает с брендом.

Ключевые слова: `login`, `verify`, `secure`, `account`, `update`, `bank`, `confirm`, `password`, `bonus`, `free`, `prize`, `kaspi`, `halyk`, `signin`, `wallet`, `payment`, `reward`. Поиск идёт по подстрокам, поэтому `bank` также учитывается внутри более длинного слова.

Потенциальные зоны риска: `.xyz`, `.top`, `.click`, `.zip`, `.work`, `.loan`, `.gq`, `.tk`. **Наличие такой зоны не доказывает мошенничество.** В этих зонах могут находиться обычные сайты, а опасная ссылка может использовать любую другую зону.

## Примеры

Все примеры разбираются локально; сайты не открываются.

```python
from ml.url_features import extract_url_features, explain_url

features = extract_url_features(
    "https://login.example.com/verify?user=123"
)

print(features)
print(explain_url(features))
```

Обработка ошибки:

```python
from ml.url_features import validate_url

try:
    validate_url("ftp://example.com")
except ValueError as error:
    print(error)  # Допустимы только схемы HTTP и HTTPS
```

## Ограничения

Признаки не являются ML-классификацией и не доказывают безопасность или мошенничество. Не исследуются содержимое страницы, редиректы, доступность, сертификаты и репутация. HTTPS сам по себе не подтверждает добросовестность сайта. Списки брендов, слов и сокращателей неполные, снимок PSL не обновляется при анализе. Похожие легитимные домены могут давать ложные срабатывания; нестандартные маскировки могут быть пропущены. Расстояние сравнивается по полному зарегистрированному домену, включая суффикс; визуальные омоглифы не заменяются латинскими аналогами. Смешение проверяется по всему host, поэтому обычный кириллический домен с латинской зоной тоже активирует этот признак. IDNA использует стандартный кодек Python, без отдельной реализации браузерного UTS #46. IPv6 с зоной интерфейса не поддерживается. URL без схемы с портом распознаётся для доменного имени с точкой, IPv4, IPv6 в скобках и `localhost`.
