Задание № 6 использует 5 135 англоязычных сообщений из `data/processed/sms_clean.csv`. Искусственный набор ru/kk в разбиение не входит.

Разбиение стратифицированное. Сначала выделяется 30% корпуса, затем эта часть делится пополам. Оба вызова используют `random_state=42`. Разница в одной строке между validation и test возникает при округлении. Ключи `train`, `validation` и `test` в `data/processed/sms_split.json` хранят позиции строк CSV с нуля в порядке передачи в пайплайн. Для повторного использования нужен тот же порядок строк в `sms_clean.csv`.

## Что измеряет TF-IDF

TF-IDF присваивает признаку вес с учётом его частоты в одном сообщении и распространённости в корпусе. TF отражает число вхождений. При `sublinear_tf=True` для словесной ветви ненулевая частота заменяется на `1 + log(tf)`, чтобы многократное повторение слова не увеличивало вес линейно. IDF повышает относительный вес признаков, встречающихся в меньшем числе SMS. С настройками сглаживания scikit-learn он равен `log((1 + N) / (1 + df)) + 1`, где `N` — число обучающих сообщений, а `df` — число обучающих сообщений с данным признаком. Каждая из двух ветвей TF-IDF по умолчанию нормирует свои строки по L2.

Словесная ветвь учитывает отдельные слова и соседние пары. Биграмма `claim prize` сохраняет контекст, который теряется при подсчёте слов по отдельности. Параметры `min_df=2` и `max_df=0.95` исключают признаки, встретившиеся лишь в одном обучающем SMS или более чем в 95% обучающих SMS. Символьная ветвь строит фрагменты длиной 3–5 символов внутри границ слов (`char_wb`) с пробелами у краёв. Такие признаки могут частично совпасть при опечатке или намеренном искажении слова, даже если словесный токен целиком изменился. Они также фиксируют части служебных маркеров вроде `<num>`.

`FeatureUnion` объединяет 8 782 словесных, 47 886 символьных и 6 ручных признаков. Матрицы хранятся в разреженном формате. Ручные признаки включают длину исходного SMS, долю заглавных среди букв исходного текста, число `!` в исходном тексте, наличие `<url>` и `<money>` после нормализации и число сработавших групп. Минимальный английский словарь охватывает срочность, деньги и переводы, банк и карту, блокировку аккаунта, выигрыш и приз, запрос кода и пароля. Каждая группа учитывается максимум один раз на сообщение.

## Воспроизведение после клонирования

Из корня проекта создайте и активируйте виртуальное окружение по README. Ниже пример для Windows PowerShell с Python 3.12. Для установки зависимостей и первой загрузки архива UCI нужен интернет.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/init_env.py
python ml/data/load_sms.py
python -m ml.preprocessing
python -m ml.features
python -m pytest -q -p no:cacheprovider
```

Загрузчик скачивает официальный архив UCI, проверяет SHA-256 и создаёт `sms_raw.csv`. Предобработка создаёт `sms_clean.csv`, а модуль признаков сохраняет `sms_split.json`. Эти файлы генерируются локально и исключены из Git. Для восстановления индексов используйте исходный порядок строк и версии зависимостей из `requirements.txt`.

Загрузчик признаков выводит топ‑15 по среднему TF-IDF для каждого класса на train. Среднее включает нулевые значения. Ручные признаки в рейтинг не входят. Первое место у `ham` занимает словесный признак `you` (0,031828), у `spam` — `num` (0,121118). Символьные фрагменты одного маркера могут занимать несколько соседних мест.

`create_feature_pipeline()` принимает последовательность исходных SMS, применяет `normalize_sms()` и возвращает разреженную матрицу. Обе ветви TF-IDF обучаются только на train. Validation и test обрабатываются через `transform`. Проверены повторяемость JSON, отсутствие пересечений и полное покрытие корпуса, согласованность размерностей, ручные признаки и неизменность словарей и IDF после преобразований. Проверены клонирование пайплайна с добавленным шагом классификатора и сериализация обученного преобразователя через joblib. Классификатор не обучался.
