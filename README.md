## Запуск на Windows (PowerShell)

Требования: Windows 10/11, 64-bit Python **3.11–3.13**, Git, подключение к интернету для первого `pip install`. Откройте папку проекта в VS Code; все команды выполняйте **из каталога с `manage.py`**.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/init_env.py
python manage.py migrate
python manage.py runserver
```

Если установлена только Python 3.12 или 3.13, замените `-3.11` в первой команде на `-3.12` / `-3.13`.

Откройте:
- <http://127.0.0.1:8000/> — главная страница-заглушка.
- <http://127.0.0.1:8000/api/v1/health/> — `{"status": "ok"}`.

Дополнительная проверка (в другом окне терминала или после остановки сервера с `Ctrl+C`):

```powershell
python manage.py check
python -m pytest -q
```

Если PowerShell блокирует активацию, можно выполнить в *текущей сессии* `Set-ExecutionPolicy -Scope Process Bypass` и повторить команду активации. Не устанавливайте постоянные глобальные исключения.

## Настройки и безопасность

- `python scripts/init_env.py` создаёт локальный `.env` с новым случайным `DJANGO_SECRET_KEY`; файл исключён из Git.
- `DJANGO_DEBUG=True` предназначено только для **локальной разработки**, а не публичной демонстрации.
- По умолчанию используется SQLite (`db.sqlite3`, исключён из Git). PostgreSQL подключается на более позднем этапе.
- Логи пишутся в `logs/app.log`: время, уровень, модуль, сообщение. Максимум 1 МБ на файл, 5 резервных копий.
- Файлы в `data/raw/` и `ml/artifacts/` не добавляются в Git автоматически; публикуйте данные только при соблюдении лицензии.

## Git и дальнейшие шаги

В поставляемом ZIP находится локальная история Git с двумя коммитами: `task-01` и `task-02`.
